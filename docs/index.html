LA FÁBRICA DE CÓDIGO

tres maneras de construir software con IA — explicadas para humanos

Este repositorio guarda tres formas de trabajar con Claude para construir software. Las tres comparten una sola regla de oro: nada se da por terminado sin una prueba que lo demuestre. La diferencia entre ellas es quién escribe el código y cuánto cuesta cada línea.

Si el examen sale en rojo, se vuelve a construir con la causa exacta del fallo — no se discute con el examen, se aprueba.
//01 · elige tu método

# Las tres formas

01
Clásico

Tú y Claude trabajan juntos, como siempre — pero con un cuaderno de obra impecable. Tecleas un solo ritual (/checkpoint) y todo queda guardado: el plan, lo aprendido, el commit.

Para: empezar cualquier proyecto nuevo.
02
No-loop

Una fábrica de agentes dentro de Claude: el orchestrator reparte el trabajo, el test-agent escribe el examen antes que el código, y el veredicto llega con ojos frescos. Nadie se aprueba a sí mismo.

Para: trabajo grande que debe correr solo.
03
Híbrido

La misma fábrica, pero el código lo escriben motores más baratos: primero la tarjeta gráfica de tu propia máquina (gratis), luego la nube. Claude dirige y verifica — casi nunca programa.

Para: producir mucho gastando poco.

◢ REGLA DE ORO

Da igual el método: el examen manda. Un examen escrito antes que el código, que nadie puede editar y que hay que aprobar de verdad, convierte "creo que funciona" en "aquí está la prueba". Todo lo demás — agentes, motores, olas — existe para servir a esa idea.
